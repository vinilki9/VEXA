# VEXA Design System 0.3.14 — утверждённый стиль

**Цель:** единый визуальный язык VEXA Client, VEXA Driver, Dispatcher, Platform Admin и VEXA MAP.

## Цвета и назначение

| Элемент | Цвет | Использование |
| --- | --- | --- |
| Graphite / фон | `#151D21` | Основные экраны, меню, фоны авторизации |
| Graphite / карточки | `#202A2F` | Панели и карточки в тёмной теме |
| Graphite / поднятая поверхность | `#2B383E` | Поля ввода, вторичные панели |
| Calm Turquoise | `#54B6AA` | Основные кнопки, иконки, выделенные элементы |
| Navigation Turquoise | `#18E8D2` | **Только** активный маршрут, направления и фокус управления |
| Светлый текст | `#EDF5F4` | Заголовки и основной контент в тёмной теме |
| Вторичный текст | `#AABDBC` | Подписи, вторичная информация |
| Светлая тема / фон | `#F3F6F5` | Дневной режим |
| Светлая тема / основной акцент | `#187F76` | Контрастный бирюзовый на белом фоне |

Все основные текстовые пары проверяются на минимум 4.5:1 по WCAG AA (без претензии на полноценный аудит доступности всех компонентов).

## Реализовано в 0.3.14

- Единый файл `design/tokens.json`; `tools/sync_design_tokens.py` создаёт `VexaDesign.kt` для обоих Android-приложений и CSS-токены для двух веб-панелей.
- **Client:** главный экран, настройки и карточка статуса поездки используют Material 3 из одного набора цветовых схем. Тёмная тема по умолчанию; светлая и автоматическая сохранены.
- **Driver:** главный экран, состояние входа и экран «Деньги» используют общую палитру. Тёмная тема по умолчанию с сохранением ручного выбора.
- **Dispatcher:** графитовые карточки, меню, формы и встроенные финансовые блоки; приглушённая бирюза для действий.
- **Platform Admin:** графит, тот же приглушённый бирюзовый; отдельная проверка ролей не изменена.
- **VEXA MAP:** яркая линия маршрута в Android; фон до загрузки лицензированных тайлов — графит; обычные маркеры — спокойная бирюза в веб-панели.
- Два Android-модуля получили номера исходных версий `0.3.14`. Это **не означает**, что APK собраны.

## Как в идеале должны выглядеть экраны (дальнейший UX-этап)

**VEXA Client:** карта занимает главное пространство; снизу — компактная карточка «Куда едем?» и тарифы; при активном заказе — статусы поиска, ETA, водитель и помощь. Кнопка ⋮ ведёт в настройки. Нижняя навигация — Заказ / История / Избранное / Профиль.

**VEXA Driver:** предложение заказа всегда выше карты, ярко обозначен срок ответа; далее карта, кнопка смены статуса, «ДЕНЬГИ», смены и настройки. В пути — крупные действия навигации, безопасная работа без отвлекающих мелких контролов.

**Dispatcher:** слева меню, в центре карта и очередь заказов, справа — проблемы, водители и статусы. Для рутинного заказа не нужен ручной диспетчер.

**Platform Admin:** отдельно от диспетчерской; общая структура навигации, но расширенное управление организациями, городами, тарифами и правами доступа.

**VEXA MAP:** рельеф, спутниковые и векторные данные будут доступны лишь после законной поставки данных и завершения реализации. Яркий бирюзовый — только построенный маршрут и навигация; не заливать весь экран неоновым цветом.

## Ограничения и готовность

Это **исходники с согласованными темами**, а не подтверждённые скриншоты настоящих устройств. Часть проработанного UX остаётся планом: семейные/корпоративные функции, 3D, спутник и другие модули не добавлены этим стилистическим релизом. Реальный запуск Android, полная React/Vite-сборка и тестирование на телефонах нужны отдельно. Исходные сервисы и бизнес-логика цен/заказов в 0.3.14 не меняются.

Для будущего изменения палитры сначала редактировать `design/tokens.json`, затем запускать `python tools/sync_design_tokens.py`. Не копировать новые hex-значения вручную в отдельный экран.
