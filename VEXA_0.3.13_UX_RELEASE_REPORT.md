# VEXA Taxi — 0.3.13, UX migration phase 1

Дата: 21 ноября 2026 года. Основа: `VEXA_TAXI_TARIFF_ENGINE_0.3.12_SOURCE.zip`.

## Что реально изменено

### VEXA Client (пассажир)

- Сохранён map-first экран VEXA MAP с выдвижной панелью заказа; добавлены быстрые пункты **Дом** и **Работа** в начале панели. Адрес сначала выбирается через существующий поиск VEXA MAP, затем явно сохраняется в профиль на этом устройстве. Нажатие на ярлык подставляет координаты, сбрасывает прежний расчёт стоимости и не оформляет заказ само по себе.
- Параметры Дом/Работа изолированы по подтверждённому пассажирскому номеру (ключ хранения SHA-256), хранятся в приватных SharedPreferences и не видны другому аккаунту. В настройках можно удалить оба адреса; при возврате из настроек они перечитываются. Это **локальная** функция — синхронизация между устройствами не реализована.
- Поле **«Комментарий к подаче (подъезд, вход, ориентир)»**, до 500 символов. Отправляется вместе с запросами расчёта и создания заказа в уже существующее поле `Order.comment` Backend. Учитывается в подписи формы, чтобы смена комментария приводила к обновлению предварительного расчёта. Сам по себе комментарий цену не меняет.
- После создания заказа — системное действие **«Поделиться информацией о поездке»** (номер, откуда и куда). Это **не живое отслеживание** и не раскрывает токен входа; выбор адресата остаётся за пассажиром.
- Сохранены существующие авторизация, история, карта, тарифы и оформление заказов.

### VEXA Driver (водитель)

- Новое предложение заказа с таймером показывается **выше карты** и финансов, чтобы не требовать прокрутки перед ответом. Существующие кнопки принять/отклонить и серверная отправка ответа сохранены.
- Карта VEXA MAP перенесена в верхнюю часть рабочего экрана, её карточка выделена в `DriverHomeMapCard.kt`; город подставляется из серверного профиля, а не из фиксированной строки.
- Добавлена кнопка **«Перерыв»**, которая вызывает существующее API `DriverApiClient.setOnline(false)`; успешный переход снимает водителя с линии и немедленно останавливает GPS-службу. «Вернуться на линию» вызывает `setOnline(true)`.
- Перерыв и ручной уход с линии заблокированы в UI, если есть активная поездка (`assigned`, `arrived`, `in_progress`) или неотвеченное предложение. Проверка дополнительно должна выполняться сервером при запуске на реальном устройстве. Экранная пометка перерыва хранится только во время сессии; серверный `is_online` остаётся источником истины.
- Driver теперь получает `comment` заказа из Backend и отображает указанный пассажиром ориентир на карточке активной поездки.

### Backend

- Ответ водителю дополнен полем `comment` из уже существующей модели `Order` (без изменения структуры БД и цен). Поле не добавляется в другие публичные ответы, кроме существующих API, где оно уже присутствовало.

### Дизайн

- Единый бирюзовый акцент VEXA (`#20C6B7`), привычная схема **карта → действия → заказ** без копирования фирменных элементов других агрегаторов.
- Водительские предложения приоритетнее вторичных карточек баланса. Код карты водителя вынесен в отдельный UI-модуль, быстрые адреса пассажира — в отдельный компонент. Остальные большие экраны всё ещё требуют дальнейшего разбиения.

## Что НЕ реализовано этим обновлением

Нельзя считать готовыми: заказ к определённому времени / Smart Order, автоматический выбор режима «быстро/экономно», SOS и подтверждённое живое отслеживание, семейные аккаунты, корпоративные поездки и лимиты, чат, push-уведомления, выплаты и эквайринг, бонусы, торг за цену, совместные поездки, голосовая навигация и 3D/спутник VEXA MAP. Эти функции требуют согласованных API, БД, фоновых задач, платёжных интеграций, продуктовых правил и испытаний. В проекте есть roadmap их реализации, но UI-заглушек, имитирующих работающие сервисы, не добавлено.

## Важные ограничения

- Пользовательские «Дом/Работа» хранятся локально. После удаления приложения информация может быть потеряна; Android backup-policy следует проверить до публикации.
- Перерыв — управляемый режим «не на линии», а не автономная система рабочих смен или принудительного отдыха. Автовозврат на линию не предусмотрен.
- Поделиться поездкой можно только вручную и только текстом. Реальное live tracking потребует безопасного одноразового публичного токена с ограниченным сроком действия и права на отзыв.
- Применимость интерфейса на разных экранах, доступность элементов для TalkBack, надёжность GPS и правила локального рынка потребуют отдельных испытаний.

## Установка и запуск

1. Распаковать архив, не подменяя исходный проект до проверки.
2. В Android Studio открыть `android/client` и отдельно `android/driver`.
3. Настроить `vexaServerHost`, API и VEXA MAP согласно `README_LOCAL_SETUP.md` / серверной конфигурации, не хранить секреты в исходниках.
4. Выполнить Gradle Sync, `assembleDebug` и тестировать подключение к тестовой PostgreSQL и VEXA MAP на двух Android-устройствах.
5. Выпустить подписанные APK только после сквозной проверки: пассажир → Backend → Driver → завершение и финансы.

Исходный архив, Windows 11, VPS и GitHub в ходе этой работы не изменялись.
