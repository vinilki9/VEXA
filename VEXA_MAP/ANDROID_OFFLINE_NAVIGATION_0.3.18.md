# VEXA MAP 0.3.18 — офлайн-адреса и ограниченный дорожный маршрутизатор

Это исходный код локального поиска и маршрутизации для **VEXA Client** и **VEXA Driver**, а НЕ обещание, что в ZIP присутствуют реальные адреса, все дороги России или готовый APK. Не меняйте действующий VEXA Backend: расчёт тарифа остаётся полностью серверным.

## Архитектура

- Ранее: в `filesDir/vexa-map/offline/<district>.mbtiles` приложение хранит проверенный растровый MBTiles, отображаемый MapLibre через localhost.
- Теперь: оператор **до публикации** расширяет этот же SQLite/MBTiles таблицами `vexa_places`, `vexa_terms`, `vexa_nodes`, `vexa_edges` и метаданными `vexa_navigation_schema=v1`, `vexa_region_id=<district>`. Старый MBTiles без расширения продолжает показывать карту, но поиск и маршрутизация в нём недоступны.
- Включение: `Client` использует локальный индекс при режиме «Офлайн» или в «Авто» без подтверждённого интернета. При сетевой ошибке в «Авто» он также пытается использовать установленный индекс. В «Онлайн» работает существующий VEXA MAP API.
- `Driver` при офлайн-режиме прокладывает предварительный маршрут заказа по графу. Оба Android-приложения используют `android/shared/vexa-map-offline`, у них раздельные каталоги файлов, но единые правила загрузки, поиска и дорожного графа.
- Текст в менеджере карт: по каждому скачанному округу **«Адреса: есть/нет · Дороги: есть/нет»**; приложение не называет просто загруженную карту навигационным пакетом.
- В индекс помещаются только адреса/улицы с координатами и направленные рёбра. Время проезда должно предварительно рассчитываться поставщиком лицензированных дорожных данных. Маршрутизатор выбирает путь с минимальной суммой `duration_s`, не строит прямые линии для отсутствующих дорог.

## Подготовка регионального индекса из собственных или лицензированных данных

До публикации и до вычисления SHA-256 подготовьте 3 CSV для одного федерального округа:

| Файл | Колонки |
|---|---|
| `places.csv` | `name,latitude,longitude,rank` (rank необязателен) |
| `nodes.csv` | `node_id,latitude,longitude` |
| `edges.csv` | `source_id,target_id,distance_m,duration_s` |

`edges.csv` содержит **направленные** дороги. Для двухстороннего движения нужны две строки (A→B и B→A). Узлы должны иметь уникальный `node_id`. Координаты — WGS84 в градусах, дистанции — метры, времена — секунды. Данные должны описывать реальные разрешённые для авто проезды. Настоящие CSV необходимо подготовить отдельно; никакого автоматического преобразования OSM.PBF в дорожный индекс этот этап не выполняет.

Из **корня** VEXA, например для Центрального округа:

```powershell
python VEXA_MAP/tools/prepare_offline_navigation.py --mbtiles VEXA_MAP/data/regions/central.mbtiles --region central --places C:/vexa-data/central/places.csv --nodes C:/vexa-data/central/nodes.csv --edges C:/vexa-data/central/edges.csv
python VEXA_MAP/server/vexa_map_server.py --mbtiles VEXA_MAP/data/regions --publish-region central --data-version 2026.11.1
python VEXA_MAP/server/vexa_map_server.py --mbtiles VEXA_MAP/data/regions --verify-region central
```

**Важно:** импорт изменяет MBTiles **на месте** и использует свободное место для SQLite-журнала. Сделайте резервную копию, не выполняйте импорт одновременно с публикацией/раздачей файла. После любого изменения MBTiles пересоздайте манифест и контрольную сумму; старые версии останутся на устройствах до обновления. Приложение скачает весь обновлённый пакет, а не только CSV. Используйте отдельное защищённое хранилище/авторизованную раздачу; SHA-256 без подписи каталога не гарантирует происхождение данных.

## Алгоритм и ограничения

- SQLite открывается только для чтения. Поиск использует Unicode-нормализованные префиксы слов, ё→е, не запрашивает геосервисы при принудительном офлайн.
- Для маршрута загружается ограниченный коридор узлов/рёбер из **одного** округа, выполняется Dijkstra по времени. Максимальная прямая дистанция между точками — **90 км**, ближайший дорожный узел — **не далее 350 м**, коридор — максимум **60 тыс. узлов / 240 тыс. рёбер**. Слишком тяжёлые данные отклоняются, а не загружаются до исчерпания памяти телефона.
- Не поддерживаются маршруты через границы округов, все дороги России, повороты, реальные пробки, перекрытия, ограничения типа транспортного средства, односторонность вне входного CSV, голосовые команды, навигация с динамическим пересчётом, 3D/спутник или показ векторных PBF. Результат — **предварительная геометрия и ETA**, а не безопасная полнофункциональная навигация.
- **Для заказа такси нужен интернет и доступность VEXA Backend.** Офлайн-карта и предварительный маршрут не означают офлайн-заказ, платежи или доступность водителей. Клиентский и водительский маршрут НЕ участвуют в серверной цене поездки.
- Отображение карте использует существующие растровые MBTiles. Для продакшена нужен более производительный мобильный маршрутизатор с индексированным графом и полноценными ограничениями движения, а также отдельный векторный рендер и лицензированные геоданные.

## Проверки и честный статус

Инструмент проверен на **синтетических SQLite/CSV**: исходный тайл не исчезает, метаданные и слова индексируются, переустановка не дублирует записи, некорректная координата отклоняется, повреждённое ребро откатывает транзакцию. Kotlin-алгоритм проверен тестами направленности и выбора пути; Android-адаптер скомпилирован **с тестовыми заменами Android API**, не как APK. Эту проверку нельзя считать проверкой поведения на телефоне.
