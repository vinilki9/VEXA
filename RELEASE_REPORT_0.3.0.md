# VEXA TAXI + VEXA MAP 0.3.0 — отчёт о подготовленных исходниках

**Тип результата:** промежуточный интеграционный ZIP для Windows/Android Studio, **не готовая для эксплуатации система такси и не готовые APK**.

## Что изменено в этой копии

| Модуль | Выполненные изменения |
|---|---|
| Client | Удалены импорты/зависимости SDK 2ГИС, карта — MapLibre; поиск через локальный API VEXA MAP; получение маршрута GeoJSON и показ линии/дистанции/времени; выбор позиции через GPS; сохранены существующие формы заказов/тарифов/сессий |
| Driver | Карта на MapLibre; обновление координат GPS; отображение точек и линии активной поездки через VEXA MAP; сохранены существующие диспетчерские/финансовые экраны, логика заказов и фоновый GPS-сервис |
| Dispatcher | MapLibre GL JS вместо 2ГИС MapGL; базовый адрес карты определяется по локальному хосту; API отправляется через относительный путь к Nginx proxy |
| Backend | Исправлено закрытие HTTP-ответа OSRM для тестов и стандартной библиотеки; задан локальный URL по умолчанию вместо старого публичного VPS; основной порядок обработки заказов не менялся |
| VEXA MAP | Добавлен отдельный локальный HTTP-сервис: raster MBTiles в XYZ, style.json/TileJSON, SQLite-поиск, прокси до собственного OSRM, статус готовности. Включён в Docker Compose отдельным контейнером |
| Локальная сеть | IP ПК вместо старого VPS настраивается одновременно для Client и Driver (`tools/configure_local_ip.ps1`); backend/dispatcher/map порты — 8000/8081/8090; в Nginx добавлен proxy `/api/` |
| GitHub | Старый автоматический VPS deploy отключён; `.github/workflows/deploy.yml.disabled` хранится только для справки |

## Проведённые проверки

- Распаковка исходного `VEXA-deploy.zip` и применённых изменений — выполнены.
- Тесты нового локального сервиса VEXA MAP — **6/6 успешно**, включая MBTiles XYZ/TMS, стиль, локальный поиск и 503 при отсутствии OSRM.
- Профильные тесты Backend на маршруты, тарифы и расчёт стоимости — **44 passed, 14 subtests passed** после исправления `backend/app/routing.py`.
- Полный набор тестов Backend **не пройден**: в доступной среде отсутствует `python-jose`. Попытка установки завершилась ошибкой сетевого разрешения имён; не делайте вывод, что приложение работает в продакшене.
- Android Gradle `assembleDebug` и запуск на Android **не выполнены** (Android SDK и рабочая Gradle-инфраструктура отсутствуют в среде). Совместимость MapLibre и Compose на устройствах **не подтверждена**.
- Сборка Dispatcher TypeScript/Vite **не подтверждена**: npm-зависимости в среде отсутствуют, офлайн-установка не завершилась.
- Docker-контейнеры, PostgreSQL, интернет через локальный ПК, реальный сервер OSRM, реальные заказы и GPS на устройстве **не проверены**.
- Проверки исходников **не являются** гарантией отсутствия runtime/compile ошибок.

## Оставшиеся обязательные задачи

1. Получить разрешённые по лицензии исходные карты/растровые MBTiles по округам и обрабатывать по одному региону с учётом лимита диска 250 ГБ.
2. Создать полнотекстовую геобазу адресов; текущий SQLite CSV-импорт — только начальный механизм, а не готовая база всей России.
3. Подготовить OSRM-граф автомобильных дорог, запустить локальный OSRM и связать с VEXA MAP и Backend.
4. Реализовать полноценные офлайн-пакеты, дельта-обновления, 3D-рельеф/здания и лицензированную спутниковую подложку (пока отсутствуют).
5. Выполнить синхронизацию Gradle в Android Studio, исправить все обнаруженные ошибки, собрать debug APK Client/Driver и провести тестовые поездки на реальных телефонах.
6. Проверить Android-права GPS, фоновые уведомления, конфигурацию HTTPS для любых релизных APK, функциональность оплаты и SMS, финансовые и организационные бизнес-ограничения.
7. Перед промышленным использованием — защита каналов связи (TLS), бэкапы БД, аудит, нагрузочные тесты, мониторинг, правомерность картографических данных.

## Локальный сервер

Точная LAN IP-адресация этого компьютера неизвестна в среде сборки. Поэтому используется Android-эмуляторный адрес `10.0.2.2` по умолчанию и **автоматически определяемый адрес ПК** на Windows через `tools/configure_local_ip.ps1`. Это не фиктивный «реальный IP» и не изменение реального компьютера пользователя.

Вложенный старый `VEXA.zip` не включён в новую сборку, чтобы в архиве не осталось второй копии приложений с 2ГИС.

Реальный VPS, базы данных и оригинальные файлы пользователя не изменены. Все изменения находятся только в этой копии архива.
