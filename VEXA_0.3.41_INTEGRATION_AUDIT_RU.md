# VEXA 0.3.41 — первый этап ревизии интеграции

Дата: 22.11.2026. Основа: `VEXA_ECOSYSTEM_LEGAL_UI_0.3.40_SOURCE.zip`.

## Фактически выполнено

1. Распакован и изучен локальный архив 0.3.40; исходники Client, Driver, Dispatcher, Platform Admin, Backend и VEXA MAP присутствуют.
2. Добавлен инструмент `tools/integration_preflight.py`, запускаемый без внешних библиотек. Он проверяет ключевые пути Client ↔ Backend, наличие основных Driver API, юридический каталог, скрипты веб-сборок и Android build-файлы. Проверки являются **статическими контрактами**, не сетевыми или интеграционными испытаниями.
3. Добавлены два автоматических теста в `tests/test_integration_preflight_0341.py`.
4. Проверено 25 условий: 23 PASS, 2 BLOCKED. Заблокированы сборки Client и Driver через штатный `gradlew`: в исходном архиве нет `gradle-wrapper.jar` обоих проектов. Другие Gradle, Android SDK и подписанные APK здесь не проверены.
5. Дополнительно запущены 26 существующих тестов из четырёх наборов (`release_preflight`, `release_contracts`, `client_settings_contract`, `driver_settings_money_contract`): 26 PASS.
6. Попытка запустить полный набор Backend/Android-контрактов остановилась на отсутствующей в локальном Python-среде зависимости `python-jose`. Это **ограничение среды тестирования**, не доказанная неисправность самого Backend.
7. Не подключались VPS, GitHub, внешние сервисы; реальные БД и API не изменены.

## Существенные незавершённые вопросы

- **P0: воспроизводимые Android-сборки.** Восстановить официальные файлы Gradle Wrapper, сверить контрольные суммы из доверенного источника; выполнить `:app:assembleDebug` для Client/Driver/Navigator и сохранить протокол сборки. Нельзя генерировать фиктивный wrapper.jar.
- **P0: тестовый интеграционный стенд.** Установить зависимости из `backend/requirements.txt`, поднять изолированную PostgreSQL, применить Alembic-миграции на тестовой БД; выполнить полный `pytest` и проверку HTTP API с авторизацией и несколькими филиалами.
- **P0: сквозной заказ.** Клиент: вход по SMS (тестовый провайдер) → выбор тарифа → предпросмотр → создание заказа → предложение → назначение → принятие → прибытие → начало → завершение/отмена. Подтвердить защиту от двойных назначений и идемпотентность при конкуренции запросов.
- **P0: правовые ограничения.** Отдельно проверить модель допуска перевозчиков и журнал юридических подтверждений на тестовой PostgreSQL; утверждение документов обязательно до принудительных согласий в коммерческом режиме.
- **P0: денежные операции.** Подтвердить целочисленные копейки, расчет тарифов, комиссию/скидки по согласованной бизнес-модели, корректность балансов и отсутствие двойных списаний. В `driver_api.py` есть зависимость комиссии от рейтинга 4–10%; это требует отдельного согласования с ранее принятой базовой комиссией 10%, не заменял автоматически.
- **P1: геоданные.** Реальные MBTiles, дорожный граф ЦФО и индекс адресов отсутствуют в этом исходном архиве; без них полноценные офлайн-поездки нельзя подтвердить.
- **P1: веб-сборки и интеграция.** Проверить `npm ci && npm run build` отдельно для Dispatcher и Platform Admin, затем аутентификацию, ACL и реальную карту заказов.
- **P1: Navigator и публикация.** Проверить, что отдельный проект Navigator включён в требуемый релизный комплект, настроены Android SDK, Gradle, keystore, AAB/APK и целевые API URL. Не выдавать исходники за готовые APK.

## Запуск диагностики на Windows или Linux

Из корня `VEXA-deploy`:

```bash
python tools/integration_preflight.py
python -m pytest -q tests/test_integration_preflight_0341.py
```

Возврат кода `1` у preflight означает нерешённые блокеры. Не следует подменять его на `0` ради «зелёного» отчёта.
