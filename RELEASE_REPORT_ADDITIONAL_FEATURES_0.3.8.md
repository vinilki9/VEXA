# VEXA Taxi 0.3.8 — дополнительные функции приложений

Дата: 21 ноября 2026 г.  
Тип выпуска: **исходный код для дальнейшей сборки и испытаний**, НЕ проверенные APK и не production-релиз.

## VEXA Client

1. Кнопка **«Мои поездки»** на главном экране над адресами заказа.
2. История последних 50 поездок загружается с существующего `GET /api/v1/passenger/orders` по токену пассажира. Список привязан сервером к собственному `passenger_user_id`, не к введённому номеру телефона. Предусмотрены пустой список, загрузка, повторная загрузка и ошибки сети/истёкшей авторизации.
3. Каждая запись показывает номер, состояние, дату, адреса и цену (если есть в ответе).
4. **«Повторить маршрут»**: выбирает исходные адреса и координаты прежнего заказа; проверяет координаты и очищает старое ценовое предложение. **Это не отправка заказа:** пользователь должен заново рассчитать стоимость и подтвердить заказ.
5. Если есть незавершённый текущий заказ, повтор нового маршрута блокируется, чтобы не терять его статус. После завершения/отмены появляется **«Новая поездка»**, возвращающая к оформлению заказа.

## VEXA Driver

1. В карточке каждого активного заказа добавлены **«К подаче»** и **«К адресу»**. Передача координат только при корректных значениях широты/долготы.
2. Навигация запускается через стандартный Android Geo Intent во **внешнем установленном приложении карт**. **Это не готовая офлайн-навигация VEXA MAP**; доступность навигатора и офлайн-режим зависят от установленного приложения.
3. **«Позвонить пассажиру»** открывает стандартный номеронабиратель Android при наличии валидного номера. Автоматических телефонных звонков или разрешения CALL_PHONE нет.
4. Никакие операции заказа (статус, назначение, расчёты) эти быстрые действия не изменяют.

## Проверено

- `python -m unittest discover -s tests -v`: **15 / 15** контрактных тестов исходников, включая **9 / 9** проверок новых функций.
- `python -m unittest discover -s VEXA_MAP/tests -v`: **15 / 15** тестов VEXA MAP.
- Перепроверены реальные серверные ответы `order_to_response` и `driver_order_response`: данные, необходимые для новых экранов, уже выдаются Backend. Новых маршрутов API и миграций базы не требуется.
- Обе Android Gradle-сборки были **попытаны**, но не выполнены: Gradle Wrapper требует `gradle-8.13-bin.zip`, а `services.gradle.org` недоступен (`UnknownHostException`). Это не доказывает компилируемость или работоспособность APK.

## Оставшиеся блокеры

- Установка Android SDK/Gradle-зависимостей, сборка APK и испытания на Android.
- Проверка реального SMS-входа и E2E истории заказов с PostgreSQL/Backend.
- Проверка обработчиков `ACTION_VIEW` и `ACTION_DIAL` на разных телефонах, времени ожидания в сети, контрастности UI.
- Встроенная VEXA MAP 3D-спутниковая/offline навигация всей России не готова; текущие кнопки водителя используют установленный внешний навигатор.
- Полная платёжная интеграция, полноценные push-уведомления, безопасность и production-нагрузочные тесты остаются в работе.

VPS, GitHub и Windows 11 пользователя не изменялись.

## Следующие наиболее полезные функции

**Client:** избранные адреса «Дом/Работа», безопасная отмена заказа через API, отображение данных назначенного водителя и ETA, поддержка и квитанции.  
**Driver:** встроенная VEXA MAP навигация и офлайн-регионы, управление перерывами/сменами, причины отказа и обращение в диспетчерскую.
