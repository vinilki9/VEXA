# VEXA Taxi + VEXA MAP 0.3.4 — улучшения взаимодействия

**Дата:** 21 ноября 2026. **Исходная версия:** `VEXA_AUTH_PORTALS_FIX_0.3.3.zip`. 
**Режим:** исходники для локального Windows 11; запуск на компьютере пользователя отложен.

## Выполненные изменения

1. **Backend / Driver:** повторение того же уже принятого статуса `arrived`, `in_progress` или `completed` теперь возвращает успешный результат без новой записи `OrderStatusHistory` и без повторного начисления за поездку. Сохраняется проверка принадлежности заказа водителю и его городу, блокировка записи и запрет других переходов.
2. **Driver Android:** после принятия/отклонения предложения заказа старый кэш скрывается, даже если ответ API потерялся. При смене токена водителя предложения из прежнего аккаунта также очищаются.
3. **Client Android:** добавлен тип HTTP-ошибки с кодом ответа. Если запрос состояния заказа получил `401` либо `403`, вместо бесконечного запроса каждые 5 секунд пользователь видит просьбу снова войти. Код города по умолчанию теперь берётся из Gradle `VEXA_CITY_CODE`, а не из константы `obolensk`.
4. **VEXA MAP:** запрещены `NaN`/`Infinity` и координаты за пределами допустимых диапазонов. Некорректные расстояния, время или геометрия ответа OSRM отклоняются — маршрут не считается действительным.
5. **Авторизация диспетчера:** токены без явного типа `dispatcher` больше не принимаются. После обновления старые сессии без указания роли потребуют повторного входа. Разделение диспетчера и главного администратора сохранено.
6. **Безопасность и документация:** обновлён корневой README с действующими API, добавлен `.gitignore` для `.env`, ключей подписи, локальных карт, сборок и кэшей. Windows 11 остаётся выбранным локальным хостом, но здесь не устанавливалась и не настраивалась.

## Проверки исходников в среде подготовки

- Выборочный набор Backend, контрактов Android, миграций, расчёта цены и маршрутизации: **67 passed + 14 subtests**.
- Тесты VEXA MAP (сервер HTTP, тайлы, региональные пакеты, поиск, проверка OSRM): **15 passed**.
- Python `compileall` для сервиса карты и Backend: успешно.
- Попытка **полного** `pytest backend/tests`: сбор тестов остановилась на отсутствующем в среде `python-jose`; это прописанная зависимость проекта, но пакет в среде подготовки не установлен. Поэтому весь набор Backend-тестов **не подтверждён**.
- **Не проверены:** сборка APK через Gradle, `npm run build` для диспетчера и администратора, реальный вход в браузере, локальный Docker/PostgreSQL, SMS-провайдеры, MBTiles России, адресная база и OSRM-граф.

## Что ещё необходимо для работающего агрегатора

- Развернуть локальный сервер на Windows 11 с Docker, PostgreSQL и миграциями и проверить полный цикл заказа пассажир → диспетчер → водитель → завершение → финансы.
- Загрузить легально доступные региональные карты и адресные данные, подготовить OSRM-граф; затем проверить маршруты на границах федеральных округов и офлайн-доступ в телефонах.
- Скомпилировать и протестировать оба Android-приложения на реальном устройстве, сборки веб-панелей и права ролей в браузере.
- Для выпуска в эксплуатацию дополнительно нужны отказоустойчивые очереди, мониторинг, аудит, резервные копии, защита API от перебора, HTTPS, уведомления и полноценные платёжные интеграции.

**Важно:** это исправленная копия исходников, не подтверждённый рабочий production-релиз. Пользовательский ПК, GitHub и VPS не изменялись. Имеющиеся настоящие ключи, пароли и файлы геоданных в ZIP не включены.
