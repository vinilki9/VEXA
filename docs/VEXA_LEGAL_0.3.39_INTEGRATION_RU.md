# VEXA Legal 0.3.39 — история подтверждений

Статус: исходники для локальной проверки. **Не запускать в production до утверждения документов и правовой проверки.**

## Реализовано
- Миграция Alembic `0020_legal_history`, отдельный журнал версий подтверждений с привязкой к `user_id`.
- После успешной SMS-верификации пассажира подтверждения из сессии фиксируются под идентификатором аккаунта.
- Защищённые JWT эндпоинты для Client, Driver, Dispatcher, Platform Admin: `/api/v1/legal/account/{role}/pending`, `/history`, `/accept`. Роль задаётся конкретным маршрутом и серверным типом токена, а не пользовательским JSON.
- Существующие `/api/v1/legal/roles/{role}` и `/{role}/{document_id}` открывают полные тексты для чтения.
- Изменение `version` или `sha256` обязательного документа возвращает его в список `/pending` без изменения исторических записей.

## Не реализовано / ограничения
- UI новых обязательных подтверждений после изменения документа в Driver/Dispatcher/Admin и Navigator, блокировка защищённых бизнес-операций при `pending` и проверка повторного согласия в момент новых действий. **Эти endpoints сами по себе не блокируют работу сервисов.**
- Юридически утверждённые документы и реквизиты оператора, классификация оснований обработки данных, полномочия подписантов. Тексты в каталоге помечены как проекты.
- Независимое защищённое архивирование журналов, доверенная метка времени, отзыв рекламных согласий и исполнение запросов субъектов.
- Для анонимного Navigator нет серверного подтверждения юридической идентичности; потребуется локальная форма с отдельными правилами и корректной моделью идентификации при необходимости.
- Подписание электронного договора простой электронной подписью требует отдельно согласованных правил идентификации и использования, не обеспечивается одной таблицей.

## Следующий технический этап
1. UI просмотра документов и обновления подтверждений во всех приложениях с безопасной обработкой отсутствующего API.
2. Серверная блокировка действий, требующих принятия именно обязательной редакции договора (не блокировать право на отзыв согласия или доступ к информации).
3. Миграции и сквозные интеграционные тесты PostgreSQL и Android сборки.
4. Юридическая проверка по законодательству РФ до запуска.
