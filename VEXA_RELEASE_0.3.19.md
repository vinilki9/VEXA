# VEXA Taxi / VEXA MAP — выпуск 0.3.19

**21 ноября 2026 года** · Исходники, локальная разработка без изменений Windows, VPS, GitHub.

## Решения по пользовательским приложениям

| Компонент | Режимы | Особенности |
|---|---|---|
| **VEXA Client** | **Только сверху (2D)** | Наклон 0°, поворот 0°, запрещены жесты наклона/поворота; 3D-кнопки нет, online/offline/auto сохраняются |
| **VEXA Driver** | **2D и 3D** | Кнопка выбора режима, локальное сохранение, 0° или 55° наклона, направление по GPS (при доступном bearing), включение/выключение следования за машиной |

**2D/3D = способы отображения карты**, не подтверждение полноценного GPS-ведения по поворотам.

## Векторная карта

1. Офлайн-источник в Android читает региональные MBTiles с `metadata.format=pbf`, `metadata.json.vector_layers` и совместимым слоем `transportation` или `road`.
2. Поддерживаются рисование дорог и воды, отдельные стили подложки, плоские здания и объёмные здания **при наличии слоя `building`** (у Driver в 3D).
3. Локальный HTTP-адаптер на `127.0.0.1` отдаёт `PBF` по XYZ, переводит запросы к строкам TMS MBTiles, учитывает `gzip` и ограничивает размер данных.
4. Добавлен локальный источник глифов в пакете (`vexa_glyphs`). Подписи русских улиц и населённых пунктов включаются только при наличии нужных диапазонов SDF PBF для `Noto Sans Regular`. **Шрифты и геоданные не включены в релиз**.
5. VEXA MAP Server умеет публиковать `style.json` для PBF и загружать тайлы/глифы из региональных пакетов; `?view=3d` для Driver показывает объём зданий.
6. Обновлён общий Offline Manager: совместимые растровые и векторные пакеты доступны для кнопки «Показать на карте».

Инструмент для подготовки: `VEXA_MAP/tools/prepare_vector_mbtiles.py`. Руководство: `VEXA_MAP/VECTOR_2D_3D_0.3.19.md`.

## Развитие дорожного движка

Серверная интеграция OSRM расширена: `steps=true`, выдача очищенного и проверенного списка манёвров с типом поворота, названием улицы, координатой и расстоянием. Реальные серверные маршруты по-прежнему требуют **запущенного OSRM и подготовленного дорожного графа**. Это задел для GPS-сопоставления, навигационных подсказок и автоматического перестроения маршрута.

Существующий локальный SQLite-маршрутизатор Android **сохраняет предел 90 км** и ограничения по дорожным правилам. Он не заменён полноценным автомобильным движком. Следующий ключевой этап: графы дорог по округам, ограничения поворотов, межрегиональные переходы, самостоятельная автомобильная маршрутизация на устройстве, GPS map matching, пошаговое ведение, TTS и перерасчёт.

## Проверка на Android устройстве

1. В Android Studio установить SDK/Gradle и собрать Client и Driver.
2. Подготовить небольшой лицензированный векторный MBTiles с `transportation`, `building`, `place`, `transportation_name` и базовыми SDF глифами. Опубликовать подписанный каталог/манифест с новым SHA-256.
3. Скачать округ через Offline Manager и выполнить «Проверить».
4. В авиарежиме открыть карту Client, убедиться: 0° наклон, поворот недоступен, названия улиц есть.
5. Открыть Driver, переключить 2D/3D, проверить GPS-направление, экструзии зданий (при наличии высот), отображение маршрута.
6. Проверить восстановление сети, обновление пакета, отсутствие запросов к внешним шрифтам в режиме офлайн, пробное построение маршрута и отзывчивость интерфейса.

**Без подтверждённой сборки и тестов на устройствах выпуск остаётся исходным кодом, а не готовой навигационной системой.**
