# VEXA Route Intelligence 0.3.23 — этап 3

## Реально изменено
- `android/shared/vexa-map-offline/src/main/java/ru/vexa/offline/RouteMatching.kt`: проекция GPS на геометрию маршрута, расстояние до полилинии, сегмент и доля сегмента; фильтрация невалидных координат. **Это геометрическая привязка, не дорожный map matching по графу.** На параллельных дорогах и эстакадах не гарантирует правильный выбор.
- `android/driver/app/src/main/java/ru/vexa/driver/DriverMap.kt`: после трёх подтверждённых отклонений запускается новый запрос маршрута от текущего положения до предполагаемой цели. Для предварительной поездки цель — подача, для известных статусов `in_progress`, `started`, `on_trip`, `riding` — назначение. Неизвестные статусы требуют уточнения в реальном API. Онлайн используется `/v1/route`, офлайн — локальный `OfflineNavigation` при наличии дорожного графа. При ошибке сохраняется предыдущая линия маршрута и показывается сообщение. Смена заказа и изменение режима отменяют старые coroutine-запросы.
- `android/shared/vexa-map-offline/src/test/kotlin/ru/vexa/offline/RouteMatchingSmoke.kt`: независимые Kotlin smoke-тесты проекции, защиты от ложных перестроений, плавного направления камеры, отбора разрешённых точек посадки.

## Проверки
Успешно: компиляция чистых Kotlin-классов через `kotlinc` и запуск smoke-тестов. ZIP проверен на целостность. **Android APK не собирался; работа в приложении на телефоне не проверена.**

## Известные ограничения / следующая работа
1. Нужны реальная дорожная сеть, граф маршрутизации и достоверные ограничения остановки для Москвы и области. Без них нельзя обещать разрешённые точки посадки или корректный офлайн-маршрут.
2. Проверить реальные статусы заказа в Backend и реализовать строгую модель стадий: к пассажиру / в поездке. Сейчас предусмотрены несколько известных строковых статусов; это требует интеграционного теста.
3. Добавить map matching с учётом дорожного графа, направления движения, скорости и уровня дороги, особенно для тоннелей, МКАД, ТТК и развязок.
4. Внедрить голосовые подсказки по манёврам, не генерируя предупреждения без достоверных данных маршрута.
5. Сглаживание камеры уже частично реализовано в 0.3.22, но текущая отрисовка маркеров и `animateCamera` на каждый GPS-апдейт требует оптимизации на реальном Android.
6. Для тестов на Москве и области нужны реальные маршруты, обезличенные GPS-треки и измерения FPS; сбор логов пока не включён.
7. Не менять VPS, GitHub и production Backend без отдельного согласования.
